- 设备广播名：`NOTMESBE`（手机 App 显示大写；串口侧原设 `notmesBE`）
- BLE MAC：`FB:D7:09:D0:5B:42`
  = 串口 `AT+MAC?` 读到的 `425BD009D7FB` 的**字节序反转**（蓝牙 public address 显示惯例），
  两处数据 double-check 为同一地址。
- 连接指示：**D1 红灯亮** = CONNECT 信号（底板 J1-7 → U1-10 驱动，R3 限流）——硬件层确认连接建立。

  - 串口 → 手机：串口发送 `yolo`（hex: 79 6f 6c 6f），手机端通知收到 ✓（CCCD 已订阅）

## 测试流程（复现用）

1. 模块上电：USB-TTL 供电 + 串口助手 115200 8N1（模块 AT 固件 115200，需带 CRLF 换行）。
2. 手机 App（GATT 客户端类，如 nRF Connect / 蓝牙调试助手）扫描 → 连接 `NOTMESBE` → D1 亮。
3. **方向 A**：手机在"写入特征"发 UTF-8 文本 → 串口助手应原样出现。
4. **方向 B**：手机订阅"通知特征"→ 串口助手发送文本 → 手机收到通知。
   - ⚠️ 串口发送内容**不能以 `AT` 开头**（会被模块当命令吞掉）。

## 已知坑位备忘（本线历史）

- LPR（J1-9）必须外部拉高（J1-9 ↔ J1-12），否则不发；别名：内部上拉不可靠。
- 波特率 115200（说明书 p4 的 38400 有误）。
- "同名相接"坑只在 ESP-01S USB-TTL 工具板上（工具 TXD→模块 TXD）；MCU 侧接线未验证，按标准交叉先试。
- 指令必须带真字节 CRLF（0x0D 0x0A）；`AT+ADV?` 不存在（只有写命令 `AT+ADV=1/0`）。

## MCU 接入 —— 完成 ✅（2026-10-09 晚）

### 接线（全脱版，USB-TTL 已退役）

| RA4M2 侧 | 蓝牙 J1 | 作用 |
|---|---|---|
| 标 3 排针第 6 孔（P101/TXD0） | 左列第 5 根（脚 2 / RXD） | MCU 发 → 模块收 |
| 标 3 排针第 7 孔（P100/RXD0） | 左列第 4 根（脚 3 / TXD） | 模块发 → MCU 收 |
| 面包板 GND 母线 | J1 的 GND 脚（5/11） | 共地（必须，电池模式亦然） |
| 面包板 3V3 → J1-6/12 | — | 排针模式=供电；电池模式=LPR 电平源 |

- **标准交叉接法一次通过**（无需对调；"同名相接"玄学仅存在于 ESP-01S 工具板）。
- 供电：排针 / 电池两种模式（J3 跳线帽 [P+]/[B+] 二选一），接线完全相同。

### MCU 侧软件（hal_entry.c + app_config.h）

- FSP 新栈 `g_uart0`：SCI0、115200-8N1、回调 `bt_uart_callback`。
- 行为：每 5s 播报 `[RA4M2] lux=… T=…C RH=…%`；`read` → 即时回帧；`ping` → `pong`；
  其它文本 → `echo:`。非阻塞收发；发送内容不以 "AT" 开头（铁律）。

### 联调结果（20:56 / 21:07）

- **MCU → 手机**：手机 App 收到实帧，hex 解码 `[RA4M2] lux=0.0 T=25.9C RH=49.3%` ✓
- **手机 → MCU**：`read` 收到回帧、`ping` 收到 `pong` ✓
- **双向全链路闭环**：传感器 → RA4M2 → SCI0 → BLE → 手机（及反向命令链）✓
