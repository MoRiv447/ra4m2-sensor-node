# 软件 I2C 改造记录 —— 2026-10-09

## 目标与结果

- **目标**：把 BH1750 + BMP280 的总线从硬件 SCI2（P301/P302）迁到 GPIO 位操作软件 I2C，
  腾出 SCI2 给 WiFi 模块（第 4 篇"双无线"的前置工程）。
- **结果**：✅ 全通。传感器读数正常（BH1750 光照、BMP280 温度/气压），
  其余链路（ADC / DHT / TSN / 蓝牙）不受影响。

## 最终参数

| 项 | 值 |
|---|---|
| 引脚 | SCL = P000、SDA = P001（标 2 排针第 6、7 孔，从上往下数） |
| 速率 | 半周期 20µs（≈25kHz；宁慢勿错） |
| SCL 驱动 | **推挽**（BH1750/BMP280 不做 clock stretching，推挽安全） |
| SDA 驱动 | 输出低 / 释放（输入 + **内部上拉**）—— P000/P001 板载无上拉 |
| 时序加固 | start：SDA 释放后先等半拍再抬 SCL；stop：STOP 上升沿后补一段爬升时间 |
| 诊断（保留） | 启动打印 `[SW-I2C] idle SCL/SDA` + `[DIAG]` 六项逐段诊断 |

## 排障链条（三个坑，从浅到深）

**坑 1 —— 无上拉（NACK 全灭）**
板载 I2C 上拉（R26 = 4K7）挂在 P301/P302 网络上，P000/P001 没有上拉。
软件 I2C 的"高"靠上拉建立 → 释放全是浮空 → 扫不到任何器件。
修复：释放时启用内部上拉 + SCL 推挽（把上拉依赖只留给 SDA 一侧）+ 降速到 25kHz。

**坑 2 —— 边沿窗口**
start/stop 里 SDA 释放后立即进行下一步，没给爬升窗口（restart 场景尤其敏感）。
修复：补延时。（实测 SDA 上升仅 ~2µs，属"窗口缺失"而非"上拉太慢"。）

**坑 3 ——【最深】probe 短探测污染总线**
`i2c_bus_probe` 曾被写成"发读地址 + 立即 STOP"的短探测：从机被读地址点名后进入
**数据输出状态**，"半截读"的 STOP 与它的输出冲突、把它卡在输出模式；紧接着的下一个
事务位流全部错拍——**写命令返回 FSP_ERR_ABORTED(18)、读 ID 得到 0x03；隔 1ms 也救不回**。
决定性证据链：
- probe 后立即写 = 失败；probe 后隔 1ms 写 = 失败；**不 probe 直接写 = 成功**；
- 完整读 1 字节（数据拍 + NACK 收尾）不产生污染。

修复：probe 改回**"完整读 1 字节"**探测。

> 教训：这是软件版改写时对硬件版设计的"优化"回归——硬件版原设计本就使用"读 1 字节"探测。
> 对 I2C 这类"从机状态机深度参与"的协议，任何改变**事务边界**的"优化"都要重新验证。
