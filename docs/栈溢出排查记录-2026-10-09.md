# 栈溢出排查记录 —— 2026-10-09（WiFi 接入后整机静默卡死）

> **状态：已修复并验证通过（2026-10-09 深夜）。** 调试探针于验证后撤除。
>
> **结论先行**：主栈溢出。WiFi 首次上报的调用链实测 **1032~1064 字节**，而原主栈只有 **1024 字节**；
> RA4M2 是 TrustZone 器件，启动时设置了 MSPLIM 栈限寄存器 —— **栈指针一越过栈底就立即触发硬件异常**，
> 默认异常处理里是 `__BKPT` → 表现为"完全静默的卡死"。
> 与 WiFi 模块、接线、中断均无关 —— 所以"整块模块全拔"也一样卡。

## 1. 现象（修复前，探针固件实测串口日志）

- 前 20 拍（0.5s/拍）全部正常：`tick #1` ~ `tick #20` 稳定输出；
- 各段打点成对：`i2c-seg begin/end`（#6/#12/#18）、`dht-seg begin/end`（#8/#16）、
  `bt-report begin/end`（#10/#20）；
- **`#20` 的 `wifi-report begin` 之后：无 `end`、无任何后续输出（锁死）。**
  ⇒ 卡点 = 第一次执行 `wifi_bridge_report()`。

## 2. 根因链（数据取自问题版 ELF 反汇编与工程源码，可复现）

| # | 环节 | 事实 | 出处 |
|---|---|---|---|
| 1 | 主栈容量（原） | **1024 B（0x400）** | `bsp_cfg.h:31` `BSP_CFG_STACK_MAIN_BYTES (0x400)`；配置项 `configuration.xml` → `config.bsp.common.main` |
| 2 | 栈限寄存器 | 启动即 `__set_MSPLIM(栈底)` | `system.c:349`（RA4M2 具 TrustZone：`bsp_feature.h:589 = 1`） |
| 3 | 越界后果 | SP 越过栈底 → 栈溢出类硬件异常 → `Default_Handler` → `__BKPT(0)` | `startup.c:64/70`；`bsp_common.h:759` |
| 4 | 是否够用 | 链和 **1032 B > 1024 B ⇒ 越界**（完整最深 1064 B） | 帧表和计算（见下） |

### 实测各帧（objdump 读函数序言，单位：字节）

| 函数 | 帧 | 组成 |
|---|---|---|
| `hal_entry` | 264 | push 36 + vpush 8 + sub 220 |
| `wifi_bridge_report` | 224 | push 16 + vpush 8 + sub 200 |
| `wifi_send_cmd` | 208 | push 16 + sub 192 |
| `sniprintf`（snprintf） | 136 | push 20 + sub 116 |
| `_svfiprintf_r` | 152 | push 36 + sub 116 |
| `_printf_i` | 48 | push 48 ← **越界层** |
| `_printf_common` | 32 | 最深 1064 的最后一层（未触及） |

链和：264 + 224 + 208 + 136 + 152 + 48 = **1032**（越界）；再加 `_printf_common` = **1064**。
越界发生点 = `wifi_send_cmd` 里 `snprintf(buf, 192, "%s\r\n", cmd)` 的第一个 `%s` 转换，
`_printf_i` 压栈即越限（差 8 字节）。

## 3. 三条对照 —— 为什么这个解释能闭环

| 现象 | 解释 |
|---|---|
| 启动时 `wifi_send_cmd("AT")` 没事，#20 必死 | init 链 = 264+8+208+136+152+48 = 848 B（`wifi_bridge_init` 帧仅 8 B）；report 链多一个 224 B 帧 → 1032 B，越界 |
| 确定性卡死（每次停在同一位置） | 链路长度固定，是"第一条超过预算的路径"，与时序/信号无关 |
| WiFi 模块全拔也卡 | 死在 snprintf 的栈上，与模块/串口无关 |
| 其余功能（BLE/I2C/DHT/LDR）全正常 | 其它调用链帧和均明显低于 1024 B |

## 8. 教训（可写进第 4 篇素材）

- **嵌入式改代码先过"栈预算"**：加一条调用链（尤其套 snprintf）前，先量目标函数帧深；
  1 KB 时代很容易被"一条普通格式化链"击穿。
- **RA4M2 的静默卡死不一定是死循环**：MSPLIM 让栈溢出变成"立即硬件陷阱 + `__BKPT` 默认处理"，
  现场无任何输出——与"业务代码卡死"表象一致，需要用探针/反汇编区分。
- **FSP 默认异常处理 = `BSP_CFG_HANDLE_UNRECOVERABLE_ERROR(0)` = `__BKPT`**：接 e² 调试器时
  会停在 BKPT，是下次抓现场的最快路径。
